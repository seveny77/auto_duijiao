# VA 精扫：规划区间并选择最高分实拍帧

`fine_scan.py` 是独立的标准库脚本，不需要导入本项目其他文件，不包含软件变量接口、
相机接口或运动控制。可以按你已有的方式，将完整代码分别放到 VA 的脚本节点中，
然后在节点末尾添加下面的调用和自己的变量读写。

本版精扫从低坐标向高坐标运动，沿用起点不触发、终点触发、每帧执行一次的约定。
精扫是最后的采样阶段：采完直接选择实际评分最高的那一帧，不做拟合、不重新 NCC、
不强制补拍或重新移动。输出位置是该帧对应的指令位置，不是编码器反馈。

## 区间和帧数

设预测中心为 C，精扫步距为 S，中心单侧的拍照点数为 N。
N 不含中心点，中心本身也拍照，且所有位置单位均为 um。

```text
第一拍位置 = C - N × S
最后一拍位置 = C + N × S
总帧数 = 2 × N + 1
中心帧序号 = N（从 0 开始）

运动起点 = C - (N + 1) × S   ← 此位置不触发
运动终点 = C + N × S         ← 此位置触发最后一帧
```

一定不要把“第一拍位置”直接设为运动起点，否则第一拍会漏掉，实际帧数和位置会错配。

用用户本次 NCC 候选 `11105 um` 举例，步距设为 `5 um`，单边点数设为 `10`：

| 项目 | 数值 |
| --- | --- |
| 运动起点（不拍） | 11050 um |
| 第一拍 | 11055 um |
| 中心帧 | 11105 um，第 11 帧，frame_index=10 |
| 最后一拍 / 运动终点 | 11155 um |
| 总帧数 | 21 |

步距与点数是示例，你可以通过软件变量调整。`side_count=0` 表示只拍中心一帧，
此时仍需从中心前一个步距开始运动。

## 节点一：精扫初始化及区间计算

在运动前调用一次，并将返回 JSON 保存到单独的精扫 String 变量，不覆盖粗扫数据。

```python
# 由你读取输入变量：
# predicted_peak_um：本轮流程决定采用的精扫中心
# fine_step：精扫步距，正数，um
# fine_side_count：中心每侧拍照点数，非负整数

fine_json = initialize_fine_scan(
    predicted_peak_um=predicted_peak_um,
    step=fine_step,
    side_count=fine_side_count,
)
plan = json.loads(fine_json)

fine_start_um = plan["start_position"]  # 运动起点，不触发
fine_end_um = plan["end_position"]      # 运动终点，触发
fine_expected_count = plan["expected_count"]
fine_motion_step = plan["step"]

# 由你的接口保存 fine_json、起点、终点、步距、预期帧数。
# 清空上轮缓存的最佳图像和完成标志，先定位到 fine_start_um，再开始本轮扫描。
```

本次你给出的 NCC 候选为 `11105`；若使用此前完整联调调用片段，应采用其
`flow_peak_um` 或已选好的 `predicted_peak_um` 局部变量，以兼容“无候选时用粗扫最高点”
的情况。精扫函数接收位置，不会重新检查 NCC 的 `valid` 或质量阈值。

如果已有设备允许行程，请同时传入，校验范围包含不拍照的运动起点：

```python
fine_json = initialize_fine_scan(
    predicted_peak_um=predicted_peak_um,
    step=fine_step,
    side_count=fine_side_count,
    travel_min_um=allowed_min_um,
    travel_max_um=allowed_max_um,
)
```

没有提供的那一侧不做限位检查，仍需依赖你的运动流程和 PLC 限位。
超限直接报错，不自动裁剪区间；否则无法保持你要求的左右点数和中心采样。
下发运动后不要中途更改计划或重新初始化。

## 节点二：每帧清晰度计算完成后更新

```python
# current_sharpness：当前精扫帧的清晰度，单个数值
# previous_fine_json：从精扫 String 变量读取的上一帧累计记录
fine_json = append_fine_sharpness(
    sharpness=current_sharpness,
    history_json=previous_fine_json,
)
data = json.loads(fine_json)

current_is_best = data["current_is_best"]
best_frame_index = data["best_frame_index"]
best_frame_number = data["best_frame_number"]
best_position_um = data["best_position_um"]
best_sharpness = data["best_sharpness"]
fine_complete = data["complete"]

# 保存 fine_json，下一帧将它作为 previous_fine_json 传入。
if current_is_best:
    # 在这里添加你的图像保留操作：将当前精扫帧复制/保存为最佳帧。
    # 需保留实际像素或独立图像文件，不能只保留会被下一帧覆盖的相机缓冲区引用。
    pass
```

函数按初始化的计划计算位置，不需要每帧再传起终点和步距。
每帧只调用一次；图像与评分必须来自同一帧。

`current_is_best=True` 表示最新追加帧被选为目前最佳，第一帧必定为 True。
完全同分时依次优先：离预测中心更近、较早采集。
因此即使分数没有变大，新帧离中心更近时也可能要替换当前保存的最佳图像。
任何更高评分都优先于中心距离，不会为了靠近预测点而选择较低分帧。


如果按 `current_is_best` 在循环里更新图像缓存，结束时缓存中的图像就是最终帧。
如果选择保存所有精扫帧，则用 `final_frame_index` 从本轮精扫帧列表中取图。
这些序号只针对本轮精扫，不包含之前标定/粗扫的帧，也不是相机全局帧号。

**JSON 只保存帧序号、位置和评分，不保存图像本身。** 没有复制或保存图像时，
仅凭最终帧号不能恢复被相机缓冲区覆盖的那一帧。

## 完成与限制

- `complete=True` 表示计划帧已采完并记录，不是全行程对焦成功的精度认证。
- 最高分落在精扫边缘也会正常输出，只设置 `best_at_boundary=True`，不强制补拍。
- 最终结果严格从本轮精扫帧中选，不会改选粗扫帧、不输出拟合虚拟位置。
- 数据为空、计划/位置不一致、非法分数、未采完就取最终结果，或者采满继续追加都会报错。
- 只保证在本次精扫区间内选择最高分；预测中心偏差很大时，区间可能不包含真正焦点。
- 本例候选中心 11105 与粗扫最高分位置 10550 相差 555 um；上述 ±50 um 的示例窗口
  不包含 10550。当前按用户要求先联调流程，不据此宣称精度通过。
- 输出最高分帧不等于电机停在最佳位置。电机仍可能停在扫描终点；本版不额外移动或重拍。
