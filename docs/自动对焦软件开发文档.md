# 自动对焦功能开发文档（C++ 视觉平台）

> 版本：V1.0　适用平台：视觉平台软件（C++）　日期：2026-08
>
> 本文档基于 Python 原型（ct-roi 工程）的实测设计与数据，描述在 C++ 视觉平台上实现"自动对焦"功能的软件与算法设计。支持两种搜索模式：
>
> - **NCC 模式**：离线标定 + 粗扫 + NCC 预测 + 精扫
> - **DL 模式**：单帧预测定位 + 精扫

---

## 1. 概述

### 1.1 功能目标

工件来料高度随机变化时，清晰度响应曲线整体平移。系统需在尽量少的采图次数内找到最佳对焦位置（清晰度峰值对应的 Z 轴位置），并驱动电机 移动到该位置。

### 1.2 两种模式的定位

|  | NCC 模式 | DL 模式 |
|---|---|---|
| 离线依赖 | 需要标定模板（全扫一次） | 需要训练好的回归模型 |
| 在线预测输入 | 粗扫分数序列 + 模板 | 单帧定拍图像 |
| 在线采图次数 | 粗扫 ~N/10 + 精扫 ~10 | 单帧 + 精扫 ~10 |
| 适用 | 曲线形状稳定、可标定 | CT要求高、行程内图像有明显的特征区分 |

### 1.3 硬件环境（原型实测）

| 部件 | 型号/规格 |
|---|---|
| 相机 | USB3\CameraLink，黑白                                    |
| 镜头 | 显微镜头                                                 |
| 运动 | Z 轴丝杆 + PLC（汇川，Modbus TCP）\PC直驱（提供电机sdk） |
| 工控机 | Windows，GPU推理（DL 预测约百毫秒级） |

## 2. 总体架构

### 2.1 分层

```
┌──────────────────────────────────────────────┐
│ 界面层（平台 UI / 参数 / 结果显示）             │
├──────────────────────────────────────────────┤
│ 流程层 Pipeline：状态机 + 阶段编排 + CT 统计     │
├──────────────────────────────────────────────┤
│ 算法层 Strategy：NCC / DL（可插拔接口）          │
├──────────────────────────────────────────────┤
│ 硬件抽象层：ICamera / IPlc / 评价器 / ROI 检测   │
└──────────────────────────────────────────────┘
```

### 2.2 线程模型

| 线程 | 职责 |
|---|---|
| 主线程 | 界面、状态机、流程编排 |
| 采集线程 | 相机 SDK 回调，帧入队（不阻塞） |
| 评价线程 | 从队列取帧，清晰度评价 / 存图 |
| PLC 线程\电机控制线程 | Modbus 读写、飞拍/定点（阻塞调用隔离） |
| （可选）推理线程 | DL 推理（GPU），避免阻塞主流程 |

核心原则：**采集回调只入队，重活放工作线程；跨线程用队列 + 事件，禁止直接操作界面。**

## 3. 硬件接口设计（C++）

### 3.1 相机抽象接口

```cpp
enum class TriggerMode { Off, Software, Hardware };

class ICamera {
public:
    virtual ~ICamera() = default;
    virtual bool Open(int index) = 0;
    virtual void Close() = 0;
    virtual bool Capture(cv::Mat& frame, int timeoutMs) = 0;          // 单帧（软触发）
    virtual bool StartGrabbing(std::function<void(const cv::Mat&)> cb) = 0; // 回调取流
    virtual bool StopGrabbing() = 0;
    virtual bool SetExposure(double us) = 0;
    virtual bool SetGain(double db) = 0;
    virtual bool SetDecimation(int factor) = 0;   // 1/2/4
    virtual bool SetROI(int x, int y, int w, int h) = 0;
    virtual bool SetTriggerMode(TriggerMode mode) = 0;
};
```

实现注意：

- 改窗口/降采样前必须先停流（相机跨会话记忆窗口，需先复位到全幅再设置）；
- 回调中只做 `std::mutex` 保护的入队，评价/存图在独立线程；
- 像素格式统一为 Mono8/BGR8（原型踩过 16 位格式的坑，回调需处理位深转换）。

### 3.2 PLC 抽象接口（后续替换成pc直驱的sdk）

```cpp
class IPlc {
public:
    virtual ~IPlc() = default;
    virtual bool Connect(const std::string& host, int port) = 0;
    virtual void Disconnect() = 0;
    virtual bool ReadStrokeRange(int& minUm, int& maxUm) = 0;
    virtual int  Flyscan(int startUm, int endUm, int stepUm, int timeoutMs) = 0; // 返回张数
    virtual bool MoveToPosition(int index, int timeoutMs) = 0;   // 定点移动+拍照
    virtual bool ProcessComplete() = 0;
};
```

寄存器映射（汇川 Modbus，地址 = D 编号）：

| 方向 | D 编号 | 含义 |
|---|---|---|
| VA→PLC | D4002~4007 | 飞拍起/终点、步距（32 位，低 16 位在前） |
| VA→PLC | D4009 | 飞拍触发（0→1 上升沿） |
| VA→PLC | D4010~4011 | 定点序号、定点触发 |
| VA→PLC | D4012 | 流程完成 |
| PLC→VA | D4103~4106 | 丝杆行程 min/max（32 位） |
| PLC→VA | D4109~4113 | 飞拍确认/完成/张数、定点确认/完成 |

协议要点（原型踩坑总结）：触发位先清 0 再置 1（上升沿）；完成后清确认/完成位；超时需带寄存器快照便于排查。

## 4. 公共算法模块

### 4.1 清晰度评价器

```cpp
class SharpnessEvaluator {
public:
    double Evaluate(const cv::Mat& image, const cv::Rect& roi);  // Tenengrad
};
```

实现：ROI 裁剪 → 灰度 → Sobel 梯度幅值均值。原型实测 4096×3000 全幅约 200 ms/帧，decimation 4（1024×748）约 5 ms/帧，因此**评价前必须降采样**。

### 4.2 帧采集器（PhaseCollector 的 C++ 版）

```cpp
class FrameCollector {
public:
    FrameCollector(ICamera* cam, SharpnessEvaluator* eval,
                   bool keepImages, std::function<void(const cv::Mat&, int)> saveFn);
    void Start();
    void Stop();                       // 停流 + 等评价线程退出
    bool Wait(int count, int timeoutMs);
    std::map<int, double> Scores();
    cv::Mat Image(int seq);
};
```

设计要点：

- 队列上限（如 32 帧），满则丢帧（由张数校验兜底），回调绝不阻塞；
- 评价线程持有 `std::atomic` 计数与互斥的分数/图像表；
- **`keepImages` 开关**：标定不需要存图时必须关闭，否则 400 帧全幅会内存爆炸（原型实测教训）。

### 4.3 ROI 检测（YOLO）

- 输入帧由策略提供（NCC = 粗扫最佳帧，DL = 单帧）；
- 推理引擎建议 ONNX Runtime 或 TensorRT（C++ 集成友好），输出框坐标在**降采样图像坐标系**，转传感器坐标需乘 decimation 倍数；
- 失败/模型缺失 → 降级居中固定 ROI，并标记来源（detect/fallback）。

## 5. 两种搜索模式算法设计

### 5.1 公共流程（两种模式共享）

```
IDLE → INIT（PLC/相机）→ PREDICT（策略预测峰位置）→ DETECT_ROI → FINE_SCAN → FINAL_MOVE → DONE
                                                                                  ↘ ERROR / CANCEL
```

### 5.2 NCC 模式

**离线标定（只跑一次）：**

```
全扫（起点 9500µm，跨度 600~2000µm，步距 10~20µm，decimation 4）
  → 逐帧 Tenengrad 评价
  → 归一化曲线 + 峰位置 + FWHM
  → 保存模板 JSON
```

**在线搜索：**

```
① 粗扫：均匀采样（步距 100µm），飞拍 + 评价 → positions[], scores[]
② NCC 滑动匹配：对每个偏移 Δz，计算粗扫分数与模板的 Pearson 相关系数
      Δz* = argmax NCC
      预测峰 = 模板峰 + Δz*
③ 质量判定：ok / partial / mismatch / boundary / low_contrast
④ 精扫：预测峰 ± N×精扫步距（如 ±5×5µm），逐点飞拍评价
⑤ 定拍：PLC 移动到精扫最佳 index，采全幅定拍帧
```

要点：粗扫点数量少（如 6~20），NCC 计算量极小（<1ms）；质量差时精扫区间降级为粗扫峰 ±2×粗扫步距。

### 5.3 DL 模式

```
① 定拍一帧（当前 Z 位置拍照，decimation 4）
② 预处理：尺寸/灰度/归一化，必须与训练前处理完全一致
③ 推理：模型输出离焦量 Δz
      P = shot_position + Δz（clip 到行程范围）
④ 精扫：P ± N×精扫步距，飞拍评价
⑤ 定拍：移动 + 采全幅定拍帧
```

要点：

- **推理输入一致性是正确性第一前提**（尺寸、通道、归一化系数、是否居中裁剪）；
- 模型加载/预热放初始化阶段，不计入主流程 CT（原型实测初始化约数百 ms）；
- DL 输出 Δz 为相对量，必须与"基准位置"（当前定拍位置）换算成绝对位置；
- 建议推理线程独立，避免阻塞流程；GPU 可用时用 GPU，CPU 推理约百毫秒级可接受。

## 6. 策略接口设计（可扩展）

```cpp
struct PeakPrediction {
    double peak_um = 0.0;
    std::string quality;                                  // ok / partial / mismatch / ...
    double ncc_max = 0.0;                                 // NCC 专用
    cv::Mat roi_frame;                                    // 供 ROI 检测的帧（策略提供）
    std::vector<std::pair<double, double>> coarse_points; // 曲线数据（NCC 有，DL 为空）
};

class SearchContext {
public:
    ICamera* cam; IPlc* plc; SharpnessEvaluator* evaluator;
    const FocusConfig* cfg; const FocusTemplate* tpl;
    std::pair<std::vector<double>, std::vector<double>> CoarseScan(...); // NCC 用
    cv::Mat CaptureFrame();                                               // DL 用
};

class IFocusStrategy {
public:
    virtual std::string Name() const = 0;
    virtual PeakPrediction PredictPeak(SearchContext& ctx) = 0;
    virtual ~IFocusStrategy() = default;
};
```

注册表（工厂）：

```cpp
using StrategyFactory = std::function<std::unique_ptr<IFocusStrategy>()>;
std::map<std::string, StrategyFactory>& Registry();

// 注册示例
REGISTER_STRATEGY("ncc", [] { return std::make_unique<NCCStrategy>(); });
REGISTER_STRATEGY("dl",  [] { return std::make_unique<DLStrategy>();  });
```

**新增一种搜索方法 = 新类 + 注册一行，流程层不改。** 流程只依赖 `IFocusStrategy` 接口，符合依赖倒置。

## 7. 流程编排（Pipeline）

```cpp
SearchResult RunSearch(const FocusConfig& cfg) {
    auto& ctx = CreateContext(cfg);
    auto strategy = CreateStrategy(cfg.strategy);      // 注册表查
    auto pred = strategy->PredictPeak(ctx);            // 策略内部完成"预测"（粗扫或单帧）
    auto roi = DetectROI(pred.roi_frame, cfg);         // 公共：YOLO 定 ROI
    auto fine = FineScan(ctx, pred.peak_um, cfg);      // 公共：精扫
    auto final = FinalMove(ctx, fine.bestIndex);       // 公共：定拍
    return MakeResult(pred, roi, fine, final);
}
```

公共横切能力：

- **取消**：`std::atomic<bool>` 或事件标志，各阶段循环检查点；
- **超时**：飞拍确认/完成、帧等待、定拍帧等待均有超时；
- **CT 统计**：统一计时点（PLC 连接、相机设置、预测、ROI、精扫、定拍），输出与 Python 版同构的 `ct_ms`；
- **错误处理**：统一错误码 + 日志，任何阶段失败都确保"停流 → 断 PLC"的收尾。

## 9. 性能预算与优化方向

实测基线（600µm 行程）：

| 阶段 | 耗时 | 备注 |
|---|---:|---|
| PLC 连接 + 相机设置 | ~100 ms | 固定 |
| 粗扫（20 点） | ~2.3 s | NCC 模式主成本，随行程变化 |
| NCC 预测 | ~1 ms | |
| YOLO 检测 | ~40 ms | 固定 |
| 精扫（10 点） | ~0.7 s | 固定 |
| 定拍 | ~0.57 s | 固定 |

优化方向：

1. 粗扫步距 100→200µm，粗扫点减半（需验证 NCC 精度）；
2. 精扫/定拍由 PLC 运动速度决定，可调触发间隔；
3. DL 模式省掉粗扫，预测阶段仅单帧 + 推理，理论 CT 最低；
4. 评价降采样（decimation 4）是精度与速度的平衡点。

## 10. C++ 移植要点

| Python 原型 | C++ 对应 |
|---|---|
| numpy 数组 | `cv::Mat` |
| dataclass（FocusConfig/Result） | `struct` |
| PyQt 界面 | 平台 UI（Qt / MFC / 平台自带控件） |
| threading / QThread | `std::thread` + 队列 + 条件变量 |
| pyqtSignal | 回调 / 事件 |
| dict 传参 | 类型化 struct（编译期校验） |
| pymodbus | 自写 Modbus TCP 客户端（或现成库） |
| ultralytics YOLO | ONNX Runtime / TensorRT |

注意事项：

- **帧内存**：全幅 4096×3000 Mono8 ≈ 12MB/帧，队列要限深、评价完即释放；`keepImages` 语义要保留；
- **线程安全**：相机 SDK 回调、PLC 通讯、取消标志的并发访问必须加锁/原子；
- **相机收尾**：StopGrabbing → 等回调退出 → CloseDevice → 再考虑 SDK Finalize（每轮 Finalize 会导致二次运行崩溃，原型踩坑）；
- **YOLO 与相机线程冲突**：推理时相机必须停流（原型因二者并发触发 CPython 线程状态崩溃），C++ 同样建议"预测前停流"；
- **日志/配置**：统一日志组件与 JSON 配置，配置含版本字段便于迁移。

## 12. 假设与约定

- C++17 及以上，OpenCV 为图像基础库；
- DL 推理用 ONNX Runtime 或 TensorRT，模型为回归模型（输入单帧，输出 Δz）；
- PLC 为汇川 Modbus TCP，寄存器映射以本文第 3.2 节为准；
- 相机像素格式固定 Mono8/BGR8，窗口/降采样修改前必须停流；
- 本设计为功能级文档，平台 UI 集成细节（算子注册、参数面板）由平台架构决定。
