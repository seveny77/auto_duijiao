# 当前软件架构与学习路线

> 适用版本：`easyAutoFocus0904` 在 2026-09-06 完成连续精扫收敛后的版本。
>
> 本文是当前运行代码的学习入口。旧的 NCC、模板标定、粗扫/精扫、硬触发飞拍文档均只保留为历史资料，不能再作为当前流程的实现依据。

## 1. 系统现在做什么

软件完成一次任务时，只走一条自动对焦主链：

```text
人工设置相机硬件 ROI
        ↓
设置清晰度评价 ROI（位于硬件 ROI 内）
        ↓
Z 轴移动到扫描起点
        ↓
相机连续采集，回调把帧放进有界队列
        ↓                         ↓
Z 轴匀速扫到终点             后台线程计算清晰度，只保留最佳帧
        ↓                         ↓
停止采集并排空队列 ───────────→ 产生最佳原图
        ↓
把最佳原图显示、按配置保存，并提交缺陷检测
        ↓
Z 轴回到扫描起点（不计入对焦 CT）
```

这里没有 NCC 模板、没有粗扫预测峰位、没有二次精扫、也没有按位置硬件触发。扫描过程中拍多少帧由连续采集帧率和轴扫描时间共同决定。

## 2. 模块边界

| 层 | 主要文件 | 职责 |
|---|---|---|
| GUI 入口 | `gui/main.py`、`gui/main_window.py` | 创建窗口、服务对象与界面连接；不做耗时算法。 |
| GUI 参数与任务编排 | `gui/app/widgets/param_panels.py`、`gui/app/services/config_service.py`、`gui/app/services/focus_run_service.py` | 收集参数、保存配置、校验硬件状态，并在后台线程发起对焦。 |
| 对焦管线 | `backend/pipeline.py` | 组织“到起点 → 连续取帧 → 扫描 → 取最佳帧 → 保存/回位”的完整流程。 |
| 连续帧处理 | `backend/direct_fine.py` | 相机回调接收帧；用有界队列解耦采集与清晰度计算；只保留最清晰的一帧。 |
| 相机与运动 | `camera/camera_adapter.py`、`backend/camera_utils.py`、`motion/` | 相机 ROI、连续采集、曝光；以及 M60/E4O4 的定位和连续扫描。 |
| 检测 | `gui/app/services/inspection_service.py`、`gui/app/workers/inspection_worker.py`、`backend/segmentation_model_service.py` | 最佳图到达后，独立执行分割、找圆、规则判定和结果绘制；不阻塞对焦流程。 |

## 3. 线程边界

```text
GUI 主线程
  ├─ 用户操作、界面刷新、日志显示
  ├─ FocusTaskService 的后台任务线程
  │    └─ backend.pipeline.run_search()
  │         └─ ContinuousBestFrameCollector 的相机回调 / 帧处理线程
  └─ InspectionService 的检测工作线程
       └─ 模型推理、找圆、规则统计
```

三条必须牢记的约束：

1. 相机回调和帧处理线程不能访问 Qt 控件；它们只产生数据和回调。
2. GUI 主线程不运行运动等待、模型推理或清晰度计算，否则界面会卡住。
3. 检测拿到的是一份最终图副本；检测异常不能影响已经完成的对焦结果。

## 4. 当前最关键的配置

`gui/config.json` 中的对焦相关配置由 `ConfigService` 管理，核心项如下：

| 字段 | 含义 |
|---|---|
| `work_roi_width_px` / `work_roi_height_px` | 相机硬件工作窗口大小。用户应用后，后续对焦均在此窗口内进行。 |
| `evaluation_roi` | 清晰度评价区域，相对于硬件 ROI 的局部像素坐标；越界时自动回退为整张硬件 ROI。 |
| `search_start_um` / `search_span_um` | 扫描起点和扫描跨度。 |
| `continuous_scan_velocity_um_s` | Z 轴连续扫描速度。 |
| `continuous_capture_fps` | 连续采集目标帧率。 |
| `continuous_capture_queue_size` | 帧处理队列最大缓存数；队列满时会限制采集以避免静默丢帧。 |
| `save_dir` | 最终最佳原图的保存目录。 |

检测配置独立保存在 `gui/inspection_config.json`，不会污染对焦配置。

## 5. 推荐学习顺序

1. `gui/main.py`：程序如何启动。
2. `gui/main_window.py`：主窗口创建哪些服务，信号怎样连接。
3. `gui/app/widgets/param_panels.py`：用户实际能配置哪些对焦参数。
4. `gui/app/services/config_service.py`：参数怎样转换成 `FocusConfig`。
5. `gui/app/services/focus_run_service.py`：开始前做了哪些安全校验。
6. `backend/config.py` 与 `backend/result.py`：对焦输入、输出的数据契约。
7. `backend/pipeline.py`：完整运行时序。
8. `backend/direct_fine.py`：连续采集队列和最佳帧选择。
9. `gui/app/services/inspection_service.py`：对焦结束后怎样进入缺陷检测。

## 6. 常见排查入口

| 现象 | 先看哪里 |
|---|---|
| 点击开始没有执行 | `focus_run_service.py` 的参数/硬件状态校验和 GUI 日志。 |
| 采集帧率低或队列积压 | `direct_fine.py` 的帧率、队列容量、处理耗时日志。 |
| 清晰度 ROI 看起来未生效 | `config_service.py` 构建的 `evaluation_roi`，再看 `direct_fine.py` 的评分裁切。 |
| 最佳图没有保存 | `pipeline.py` 的最终图保存段及 `save_dir`。 |
| 对焦完成但检测没有启动 | `main_window.py` 的最终结果分发与 `inspection_service.py` 日志。 |
